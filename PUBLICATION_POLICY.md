# Publication policy

Public material is allow-listed, concise and reviewed through automated safety checks before publication. Material that is not explicitly allowed is rejected.

## Allowed content

- High-level architecture
- Public methodology
- Milestone summaries
- Public capability findings
- Aggregate test statistics
- Public roadmaps
- Version information
- Verified experimental conclusions explicitly approved for publication

## Prohibited content

- Private engine source code
- Credentials, tokens, keys, secrets or environment values
- Private configuration
- Full experiment or raw databases
- Copyrighted reference audio or lyrics
- Private audio outputs
- ACE Studio project files
- Private correspondence or personal information
- Sensitive local paths
- Proprietary datasets
- Unrestricted task reports or raw internal logs
- Protected captures or internal evidence manifests
- Any material not explicitly allow-listed

## Automatic milestone updates

Routine automatic publication may change only the public README, current status, changelog, milestone index, capability-census Markdown and individual milestone Markdown. Architecture, project history, this policy, contribution guidance, copyright and ignore rules require an explicitly scoped development task.

Only a successful originating task can propose publication. The event must opt in to public publication, satisfy a meaningful milestone criterion, pass the bounded schema and safety validation, and produce only allow-listed changes. Duplicate events do not create another commit. A failed push is retained for at most one explicit retry.
